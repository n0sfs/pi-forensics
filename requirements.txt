# Upper bounds added below (2026-08-23, Low finding #4 from the 2026-08-22
# security audit): Flask/gunicorn/cryptography previously had a floor with
# no ceiling - not an active vulnerability in any of the three (their known
# CVEs were already checked against this app's actual usage and don't
# apply), but an open-ended floor means a future `pip install -r
# requirements.txt` could silently pick up a new major release - a
# regression or a genuinely new vulnerability - with no review checkpoint
# prompting a look. reportlab is unaffected (already exact-pinned, ==4.0.8,
# no floor/ceiling question applies to it).
Flask>=3.0.0,<4.0.0
# >=23.0.0 specifically: CVE-2024-6827 is a TE.CL HTTP request-smuggling
# bug (Transfer-Encoding header not validated per RFC), fixed in 23.0.0 -
# confirmed via the Debian security tracker's own fixed-by commit
# reference, not just a changelog mention. Mitigated when nginx sits in
# front (this app's own recommended deployment - see the kiosk-bypass
# security-audit fix elsewhere in this history), more exposed on a plain-
# HTTP install with no reverse proxy. Found via the 2026-08-22 security
# audit. Ceiling <27.0.0: confirmed live against PyPI that 26.1.0 (already
# what's installed on the deployed Pi) is gunicorn's current latest -
# leaves room for that whole major's patch releases before a future major
# needs its own deliberate look.
gunicorn>=23.0.0,<27.0.0
psutil>=5.8.0
reportlab==4.0.8
mvt>=2.5.0
# >=20260715 specifically (not just "latest"): CVE-2026-40026 is an
# out-of-bounds-read + infinite-loop DoS in libtsk's ISO9660 SUSP parser,
# reachable via any pytsk3-backed route (Live Device Preview, Browse-as-
# Image, every in-image tool) on a deliberately crafted evidence image -
# exactly the anti-forensics scenario this appliance needs to be hardened
# against. Confirmed via pytsk3's own PyPI page that 20260715 bundles
# libtsk 4.15.0, the release that fixed this CVE (affected range is
# "through 4.14.0"). Found via the 2026-08-22 security audit.
pytsk3>=20260715
# Ceiling <55.0.0, deliberately wide: cryptography's own maintainers bump
# its major version on a rolling, roughly-every-few-weeks basis as a matter
# of normal (usually non-breaking) release practice, not as a semver
# breaking-change signal the way Flask/gunicorn do - confirmed live against
# PyPI that 50.0.0 is current latest (already several majors past this
# floor's 41.0.0, with 47.0.0 running on the deployed Pi right now) before
# picking this ceiling. A tight ceiling here would just mean this file
# needs re-touching every few weeks for no real security benefit; this
# still gives the audit's actual concern (an infinite, no-checkpoint floor)
# a real, finite bound.
cryptography>=41.0.0,<55.0.0
volatility3>=2.11.0
