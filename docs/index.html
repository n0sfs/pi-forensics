THE CASE FOR IT

A write-blocker and imaging appliance shouldn't cost more than the drives you're imaging.

Originally published as academic research — "Low Budget Forensics using ARM Based Single Board Computers" — and substantially extended since.

Dedicated appliance

The traditional path

  • A commercial imaging workstation or hardware write-blocker, often priced out of reach for a student or a small shop
  • Fixed-function hardware you can't extend, field-repair, or repurpose
  • License renewals and vendor lock-in for a workflow that's fundamentally: image it, hash it, write a report
Pi Forensics Suite

An ARM board and this software

  • A Raspberry Pi or comparable ARM SBC, storage, and a USB write-blocker adapter — commodity hardware
  • The same acquisition engines examiners already trust (dc3dd, ewfacquire, ddrescue, PhotoRec, The Sleuth Kit, ExifTool, MVT) wired together, not reimplemented
  • Self-hosted and GPLv3 — inspect it, extend it, run it entirely offline
WHAT'S ON THE STATION

One case, every tool.

Create a case once; acquisition, recovery, mobile, and reporting all auto-fill against it.

01 — ACQUISITION

Bit-for-bit imaging

dc3dd, dcfldd, plain dd, E01, and AFF, plus ddrescue for failing drives with a Mapfile Inspector. MD5/SHA-1/SHA-256 verification on every job, with every USB device write-blocked by default.

02 — RECOVERY

File recovery suite

PhotoRec, extundelete, foremost, scalpel, and read-only TestDisk partition analysis in one tool selector — one source/destination/case layout, one terminal, instead of a screen per tool.

03 — MOBILE

iOS & Android acquisition

Full iOS backup via idevicebackup2 (with optional encrypted Keychain capture) and Android via adb pull/backup/bugreport. Reads real device detail — model, OS version, IMEI, MACs — before you start.

04 — FILE EXPLORER

Browse inside an image

An in-process Sleuth Kit engine (pytsk3) walks a real folder tree down to individual files — recursive search, a MACB timeline, hex dumps, EXIF/GPS metadata, and an inline KML map, all with no mount step.

05 — REPORTING

DFIR-structured case files

A timestamped Case Notes journal, a separate Report Narrative, per-job records, and a station-wide audit trail — exported to PDF or HTML as a Standard, DFIR, or law-enforcement report, or a template you build yourself.

06 — STATION

Runs itself

TLS certificate generation with correct SANs, one-click tool installs, SMB/NFS/SFTP mounting with encrypted auto-reconnect on reboot, and network IP configuration with an automatic revert if you lock yourself out.

ON SCREEN

Guided, not bare-metal.

Every screen ships with inline help — nothing here requires memorizing dd flags.

THREAT MODEL

Built for evidence, not a demo.

This station runs privileged disk commands and often sits on a network the examiner doesn't fully control. Security isn't an afterthought layered on top.

Read the full security model →
  • Unprivileged service account — root reached only via an exact-match sudoers allowlist, never a general shell
  • Real per-examiner accounts — hashed passwords, group-based permissions across 7 gated capabilities, brute-force lockout
  • Software write-blocking — every USB storage device forced read-only at insertion by default
  • Append-only chain-of-custody log — every action timestamped, with CSV export
  • Network-change auto-revert — a bad IP setting rolls itself back before it can lock you out
ONE COMMAND

From a fresh SD card to a running station.

Flash Raspberry Pi OS (64-bit, with Desktop), boot, and run the installer — it configures the sudoers scope, systemd service, udev write-blocking, kiosk autostart, and an optional self-signed TLS reverse proxy.

# clone and install in one line
$ sudo git clone https://github.com/n0sfs/pi-forensics.git \
    /opt/pi-forensics && cd /opt/pi-forensics \
    && sudo python3 install.py

# reachable on the LAN once complete
$ open https://<PI_IP_ADDRESS>
