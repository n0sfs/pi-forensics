# Hardening changelog

## Implemented in this release

### Authentication & secrets
- Weak / missing `FORENSIC_PASS` rejected at runtime (503 until fixed)
- Installer refuses passwords shorter than 10 characters or known defaults
- `secrets.compare_digest` for constant-time comparison
- Private-range auth bypass disabled by default

### Process & filesystem safety
- No `shell=True` anywhere
- Absolute paths for all privileged binaries (match sudoers)
- Path allow-list for browse/copy/delete/report/hash/mapfile
- Device-name regex for all block-device inputs
- Host/share validation before mount or share listing
- Case/evidence identifiers sanitised

### Credential handling
- SMB mounts use a temporary credentials file (mode 0600) under `/opt/pi-forensics/run/`
- File deleted in a `finally` block after mount
- `smbclient` listing uses `PASSWD` environment variable instead of `user%pass` on argv

### Concurrency
- `threading.RLock` around all reads/writes of `current_job`
- Single acquisition at a time enforced

### Network posture
- App binds only to 127.0.0.1:5000
- nginx terminates TLS, redirects HTTP→HTTPS, sets HSTS and basic security headers
- Self-signed cert generated by installer (replace for production multi-host use)

### Write-blocker behaviour
- Drive discovery no longer forces `--setro` on every disk
- RO state is queried and displayed; explicit toggle still available
- Global USB RO udev rules remain as a baseline

### Installer
- Interactive strong password (or generated)
- Creates `/opt/pi-forensics/run` (0700) for ephemeral credentials
- Validates sudoers with `visudo -c`
- Enables nginx + gunicorn units

## Recommended operational controls
- Firewall: allow 443 (and SSH) only from trusted networks
- Prefer hardware write-blockers for evidentiary imaging
- Replace self-signed cert with internal CA when needed
- Rotate `FORENSIC_PASS` periodically
- Keep `FORENSIC_AUTH_BYPASS=0` in production

## Nginx / kiosk TLS notes (field appliance)

- **Auth stays in app.py**, not nginx. Loopback (kiosk) is allowed without Basic Auth so Chromium can load the UI on boot. Remote clients still authenticate.
- **Self-signed cert**: kiosk Chromium is launched with `--ignore-certificate-errors` and `--allow-insecure-localhost` so the interstitial does not block touchscreen use.
- **client_max_body_size 0**: unlimited body size for large evidence attachments and report JSON on a local appliance.
- **proxy_buffering off**: live acquisition progress / log streaming is not delayed by nginx buffering.
